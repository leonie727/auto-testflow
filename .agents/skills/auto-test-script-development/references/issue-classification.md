# 问题分类规则

## 1. 分类原则

1. 分类必须基于实际文件、运行证据和手动验证结果。
2. 自动化测试失败不等于系统问题。
3. 手动操作成功不一定立即证明是脚本问题，还要排除数据、角色、环境和执行时机差异。
4. **本地成功不能单独作为系统问题结论**（例如线上失败、本地成功）。
5. **数据问题不得描述成系统问题**。
6. 单一错误行不能替代完整调用链。
7. 证据冲突、缺失或无法复现时，使用 `UNCONFIRMED`。
8. 分类与处理门禁分开：`SCRIPT` 证据满足并完成确认后，状态才进入 `SCRIPT_CONFIRMED`。
9. Playwright 与 Puppeteer 的证据采集 API 分开，但使用同一分类标准。

## 2. 分类与处理对照

| 分类 | 含义 | 代码 | 记录 | 对外输出 |
| --- | --- | --- | --- | --- |
| `SYSTEM` | 产品在有效条件下手动同样失败，违背已确认预期 | 禁止修改 | 是 | 【系统异常通报】 |
| `DATA` | 数据缺失、失效、冲突或不满足前置条件 | 禁止修改 | 是 | 【数据问题通报】 |
| `SCRIPT` | 产品手动正常，证据指向自动化定位/等待/监听/断言 | 仅 `SCRIPT_CONFIRMED` 后最小修补 | 是 | 【脚本修复说明】 |
| `ENVIRONMENT` | 依赖、浏览器、权限、会话或网络差异 | 禁止修改 | 是 | 环境证据记录 |
| `UNCONFIRMED` | 证据不足、冲突或无法稳定复现 | 禁止修改 | 可选 | 仅分析，暂不改代码 |

## 3. SYSTEM

### 定义

在已确认环境、角色和前置数据下，产品实际行为稳定地不符合已确认业务预期，并且手动操作能够复现。

### 正向证据

- 按最小手动步骤操作同样失败。
- 页面缺少业务规则要求的入口、控件或结果。
- 后端接口在可复现条件下稳定返回错误。
- 保存操作显示成功，但按真实业务查询无法回显。
- 实际业务结果与产品需求、验收标准或已确认预期不一致。
- 不依赖自动化 selector 的独立证据能够复现问题。

### 反向证据

- 手动操作在相同角色、环境和数据下正常。
- 失败只发生在 locator、监听、等待或脚本断言阶段。
- 更换有效数据后功能正常（倾向 `DATA`）。
- 失败只在某台机器、某组权限或某个网络条件下出现（倾向 `ENVIRONMENT`）。
- 产品预期本身尚未确认。
- **仅有「本地自动化成功」而无手动复现与数据/环境确认**（不得据此判 `SYSTEM`）。

### 允许修改脚本

否。不得为了自动化通过而绕过、兼容或隐藏系统异常。

### 下一步

1. 固化最小复现步骤。
2. 保存页面、Network、Console、接口响应和截图证据（脱敏）。
3. 生成【系统异常通报】。
4. 调用 `save_test_issue_record`。
5. 生成 PM 评论草稿，待用户「确认回填」后再提交。

## 4. SCRIPT

### 定义

产品在已确认条件下工作正常，但自动化实现未正确观察、等待、操作或断言真实业务状态。

### 正向证据

- 相同角色、环境和数据下，手动操作正常。
- selector 失效、范围过宽/过窄或定位了错误元素。
- 等待条件与真实业务状态不匹配。
- popup、target、下载或接口监听注册时机错误。
- 脚本在页面状态稳定前读取结果；async 缺少必要 `await`。
- 脚本断言超出当前用例的已确认验证目标。

### 反向证据

- 手动操作同样失败。
- 前置数据缺失或状态错误。
- Cookie、权限、依赖、浏览器或网络环境与基线不同。
- 业务预期尚未确认。
- 只有增加固定等待后偶然成功，没有可观察状态证据。

### 允许修改脚本

是，但只有完成证据确认并标记为 `SCRIPT_CONFIRMED` 后才允许。用户说「先不要改代码」时禁止进入修补。

### 下一步

1. 定位失败调用阶段和最小根因。
2. 设计小范围修改并获确认（若流程要求）。
3. 运行目标测试。
4. 生成【脚本修复说明】并记录。

## 5. DATA

### 定义

自动化和产品功能本身可能正常，但目标测试依赖的数据不存在、失效、冲突或不满足业务前置条件。

### 正向证据

- 测试依赖数据已被删除或重命名。
- 数据状态不满足测试前置条件。
- 共享课程、考试、批次、图谱或账号数据失效。
- 搜索条件与当前数据不匹配。
- 前一次失败留下未清理数据，导致本次重复或冲突。
- 同一功能使用有效数据可以正常完成。

### 反向证据

- 已确认数据完整且状态正确，手动操作仍失败。
- 自动化读取了错误的页面区域或错误响应。
- 只有特定机器、权限或网络环境失败。
- 产品不接受本应合法的数据（倾向 `SYSTEM`）。

### 允许修改脚本

否。不得通过改 selector、删除断言或写死新的共享数据掩盖数据问题。

### 重要

数据问题必须使用【数据问题通报】，**不得**写成【系统异常通报】或口头称为系统问题。

### 下一步

1. 确认数据标识、状态、归属角色和生命周期。
2. 生成【数据问题通报】。
3. 调用 `save_test_issue_record`。
4. 生成 PM 评论草稿，待用户「确认回填」后再提交。
5. 数据修复后复验；若仍失败则重新分类。

## 6. ENVIRONMENT

### 定义

失败主要由运行位置、依赖、浏览器、权限、网络或会话条件差异造成。

### 正向证据

- 依赖缺失或安装状态不一致。
- Node、浏览器或运行容器版本差异。
- 权限、VPN、代理差异（不记录敏感值）。
- 测试环境接口偶发不可用；本地与线上、CI 与本地表现不一致且可归因于环境。
- 认证状态缺失、过期或未生成（不记录 Cookie/Token 值）。

### 允许修改业务脚本

否。

### 下一步

1. 记录环境差异证据（脱敏）。
2. 恢复基线环境后重新验证。
3. 环境一致后仍失败时重新分类。

## 7. UNCONFIRMED

证据不足以稳定归类，或证据冲突。禁止修改业务脚本；禁止生成正式系统/数据通报；输出 `MORE_EVIDENCE_REQUIRED`。

## 8. 分类决策顺序

1. 检查前置数据和运行环境。
2. 以相同角色和数据复现最小页面流程。
3. 检查页面、Network、Console、请求和响应。
4. 对比自动化已完成阶段与失败阶段。
5. 检查框架专属 locator、等待、监听和断言。
6. 给出分类及正反证据。
7. 证据不足或冲突时归入 `UNCONFIRMED`。

快速决策表：

| 手动结果 | 数据/环境 | 自动化证据 | 分类倾向 |
| --- | --- | --- | --- |
| 同样失败 | 已确认正常 | 产品结果违背预期 | `SYSTEM` |
| 正常 | 已确认正常 | 定位、等待、监听或断言错误 | `SCRIPT` → `SCRIPT_CONFIRMED` |
| 受数据状态影响 | 数据异常 | 更换有效数据可恢复 | `DATA` |
| 随运行环境变化 | 环境异常 | 基线环境可恢复 | `ENVIRONMENT` |
| 仅本地自动化成功 | 未确认 | 无线上/手动闭环 | `UNCONFIRMED`（不得判 `SYSTEM`） |
| 缺失或冲突 | 未确认 | 不足以闭环 | `UNCONFIRMED` |

该表只提供倾向，不能替代证据记录。
