# 输入模板

按场景选用以下模板，复制后填空。缺失项写「待确认」，不要编造。

---

```text
【线上现象】

【本地现象】
本机环境（OS / Node / 浏览器，不含密钥）：
执行命令：
结果：成功
与线上差异（配置 / 数据 / 账号角色 / 网络）：

【已尝试】
：

【用户约束】
是否允许改代码：是 / 否 / 先不要改代码
是否允许回填 PM：待确认后回填

【注意】
本地成功不能单独作为系统问题结论，需补充手动验证与数据/环境证据。
```

## 3. 新 PM、新脚本开发

```text
【场景】新 PM / 新脚本开发
PM编号或链接：
目标：新需求实现 / 新测试用例

【说明】
本场景不走 auto-test-script-development 异常验证流程。
请改用：
1. process-pm 路由（若从 PM 入口进入）
2. implement-pm-requirement（需求分析与脚本实现流程）
必要时可先 analyze-pm-requirement。

【用户约束】
先输出测试点与实施方案，确认后再改代码。
```

## 4. 问题记录与产品通报

```text
【场景】问题记录与产品通报
PM编号：
问题分类（SYSTEM / DATA / SCRIPT / ENVIRONMENT / UNCONFIRMED）：
用例：
场景：
现象：

【分类专用字段】
系统问题：复现步骤 / 预期 / 实际 / 证据
数据问题：数据状态 / 预期 / 实际
脚本问题：根因 / 修改位置 / 验证结果
环境问题：环境差异证据（脱敏）

【输出要求】
- SYSTEM → 生成【系统异常通报】并 save_test_issue_record
- DATA → 生成【数据问题通报】并 save_test_issue_record
- SCRIPT → 生成【脚本修复说明】（仅 SCRIPT_CONFIRMED 后改代码）
- ENVIRONMENT → 记录环境证据
- 生成 PM 评论草稿，默认不提交；用户回复「确认回填」后再 add_pm_comment
```
